# Collect review and stitch

Claude calls EN2 and downloads outputs during an active Claude Code session or a demonstrated `/loop`. postproduction.py stores durable state and runs local FFmpeg edits; it cannot invoke MCP or wake the host. The requested follow-up cadence is ten minutes. A scheduled task must demonstrate connected EN2 and local workspace access before it is recorded as active. Complete audiovisual review is performed by the user and recorded by Claude.

## Reconcile inputs before collection

The current animation/animation-manifest.json and animation/assembly-plan.json must cover the whole production, including retained dialogue. Each clip has clip_id, explicit runtime_clip_id (or identical canonical ID), content_kind, visual_format, approved inputs/hashes and used_duration_seconds. New narration boards use storyboard_1x1, storyboard_1x2 or storyboard_1x3 with a shot count chosen from the narration length and one measured cut between shots. Store source/audio/image manifest hashes. Do not automatically infer a new pairs ID from an old clip ID or split a timeline by filename.

Existing projects require a reviewed, versioned migration of these files before collecting a changed scope. Preserve prior manifests and job IDs. known_jobs rejects an unmapped scoped job. The manifest/timeline clip inventories must match. A workflow edit does not migrate production artifacts.

## Submit collect review

1. Submit all approved clips once through runtime intents in an ordered pass; save real provider IDs.
2. Poll known IDs and save an immutable snapshot. ingest filters mapped jobs and emits download-handoff.json. Record pending/failure states accurately; absent response entries are not failures.
3. Download actual returned URLs atomically and attach CLIP PATH --provider-id ID. Technical decode, dimensions and duration checks create review_pending, never visual approval.
4. Immediately after each download, inspect the complete picture and required sound of that output with all spatial, scene, cut and speech checks. Pending/failed jobs remain blockers to completion. Record named reviewer, actual observations/time ranges and hashes. review RECORD selects only verified EN2 outputs; dialogue also requires the user’s version-bound manual lip-sync verdict and original-audio alignment. Keep visual status separate; pending manual sync does not trigger regeneration.
5. After an initial visual failure, follow Animation Pack for one script-faithful scene redesign and one EN2 Ultra replacement. Reinspect it; a second failure stops for user review. Preserve failed jobs and the original logical clip ID. Local still-image/zoom animation replacements are disabled and cannot be selected, even if historical files exist.
6. advance emits remaining poll/review/repair actions and assembles ready nodes. Final delivery requires complete current-scope coverage and accepted final-node reviews.

For progress alerts, save `studio_queue` separately from individual `video_status` results. `ingest` consumes a JSON list of individual status results and emits exact download handoffs. `monitor-report --queue-snapshot PATH` reports project counts from recorded provider IDs, separate studio context, and scorecards for attached outputs. `evidence_coverage_percent` is not a quality verdict; `quality_score_percent` stays null while required checks are unverified. Only accepted review records authorize assembly. See [the scheduled check](../starling-animation-monitor/references/scheduled-check.md).

## Auto-edit before review

Run [Auto-Edit](../starling-auto-edit/SKILL.md) automatically as soon as the last raw render of the project (or of a repair batch) has downloaded: `python pipeline/auto_edit.py PROJECT`. It paces narration, trims dialogue to one spoken copy of each line, covers jump cuts, fixes or flags shot faults and writes the edited node videos, `auto-edit-report.json` and narration review sheets. Claude reads the report and inspects every sheet; the user then reviews the edited videos, not the raw clips. The edit never cuts inside approved audio, never overwrites original renders and keeps every node a separate video. Exact rules: [auto-edit rules](../starling-auto-edit/references/rules.md).

## Stitching

assemble NODE checks source hashes, exact selected-output review hashes, contiguous visual intervals and complete audio duration. Normalize approved clips to 1280x720 at 30 fps with aspect-preserving scale-to-fill and centred crop; review framing for cropped edge content. Use cumulative frame boundaries and concatenate in canonical node order. Narration, filler, establishing and ending intervals strip rendered sound and use pre-cut accepted narration units from their beginnings. Dialogue and conversation intervals retain the verified audio embedded in the selected video, with picture and sound kept together; do not replace lip-synced video dialogue with the standalone dialogue file. Measure usable dialogue duration from both streams, retain the complete final utterance and extend the node timeline when it exceeds the earlier standalone-audio interval. The assembler rejects missing embedded audio, mismatched stream starts/durations and any interval shorter than the complete selected media. Reconcile and save a longer timeline, shifting following clips and audio units, before retrying assembly. Mixed nodes require audio-unit boundaries to match each dialogue interval. Only sub-frame end padding is permitted for frame alignment; full spoken content is retained. Complete speech/lip-sync review remains mandatory because duration checks cannot identify missing words in a generated source. Normalize routed audio once to 48 kHz stereo PCM and encode AAC once for delivery. Buffered narration uses ordered source_spans in each assembly clip to trim individual shot holds before concatenation; their retained duration must equal the edit interval. Dialogue source_spans are rejected. Accepted external narration remains unchanged. Arbitrary external-audio offsets and ambience/music mixing remain unsupported. See [the timing contract](../starling-animation-pack/references/timing-and-visual-review.md).

Decode and duration checks create a final review_pending record. Review full picture, original audio, joins and word/branch coverage before accepting. Outputs are separate canonical node videos, not a concatenation of mutually exclusive outcomes. Current landscape settings must be adapted and tested before portrait delivery.

## Runtime and final package

Verified raw EN2 reviews update corresponding runtime job verification when their preflight remains current. Final-node review stays in postproduction. Accept renders and assembly receipts in runtime with all required specialist and branch checks before packaging. package requires those runtime gates and every final node's accepted review, then writes a ZIP containing videos, canonical script/choices, assembly plan, reviews and selected-output provenance.

Commands: status, ingest SNAPSHOT, monitor-report [--queue-snapshot PATH], attach CLIP PATH --provider-id ID, review RECORD, assemble NODE, advance, package. Paths stay within the project. Review-only cuts produced outside these final gates remain clearly labelled review material. No legacy review-cut helper can serve as final acceptance.

Before stitching narration, filler, establishing or ending clips, remove the complete generated audio track, including background voices, and discard subtitle/text streams. Use only the accepted external narration for those intervals. Inspect the full picture for unwanted captions, labels and overlays. Burned-in text is part of the pixels: correct/regenerate the affected scene and re-review it before assembly; dropping a subtitle track does not erase it. Preserve source-required real-world signage. Dialogue retains its verified embedded speech and lip-sync.

## Publish to the EN2 rehearsal player

EN2's `roleplay_build` accepts only the same-segment retry developer format. Export it from the canonical script with `python tools/player_export.py PROJECT/canonical-script.json OUT/script.json --language en|hi --title TITLE` (text copied verbatim; each decision becomes segment, stop and bad_outcome). Upload it as `script.json` with one edited node video per scene through `roleplay_upload` (reuse the scene file names already in that roleplay's inbox so each file replaces its old one; otherwise use INTRO, SEGMENT_n, BADOUTCOME_n, ENDING style names), then `roleplay_build` and `roleplay_status`. The user plays the sandbox and presses Make it live; Claude never does. The player shows questions and options as on-screen text only; it has no voice-over for them.
