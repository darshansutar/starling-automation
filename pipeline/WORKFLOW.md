# Starling production workflow

Current contract: 18 October 2026. Read mandatory [INTAKE.md](INTAKE.md), the production Master and the owning stage skills. This runtime preserves state and issues handoffs; ChatGPT executes MCP tools in the active session. No detached runner or automatic perceptual reviewer is installed.

## Start and resume

Use a separate project for a new source. For existing projects read status/next without reinitializing. Before building or generation ask source mode, style source and speaker voice IDs/names; read-only intake inspection can identify cast and download references. Record actual answers and inspected artifacts in intake.json. Existing project answers may be reused when source/version and choices match; never fabricate a retrospective confirmation.

```powershell
python pipeline/runtime.py --project projects/PROJECT init --title "Project title"
python pipeline/runtime.py --project projects/PROJECT status
python pipeline/runtime.py --project projects/PROJECT intake intake.json
python pipeline/runtime.py --project projects/PROJECT next
```

New projects default to all_ready_once and current reference-mode routing. Existing projects retain their history; recording intake adopts the current policy for future work. It does not migrate manifests or resubmit jobs. Reconcile existing source/image/audio/prompt receipts and job versions before reuse. Missing/changed intake blocks new acceptance/submission.

## Visual and render handoff

Approve a scene master before panels for each continuous location. Record camera axis, named screen positions, seating/standing orientation, furniture dimensions/placement, fixed landmarks, prop state and lighting. The first panel uses visible characters, environment, visible props and scene master last. Later panels use the same required appearance references with the previous approved panel or scene master last. Reject swaps/mirroring, camera-axis crossing, changed sitting orientation, furniture growth and background drift at image review.

Use one narration composition by default. Add a cut only for source-supported, person-free B-roll that reveals a different action detail, important evidence/object, environment, or location/time change that the current composition cannot show. Do not introduce another human subject, alternate portrait or repeated conversation angle as an extra narration shot. Do not use a closer duplicate of the same table/scene as filler. Dialogue animation passes exactly one approved clean full-frame scene plus accepted audio.

When narration leads directly into dialogue, plan the narration ending and dialogue opening together. They must use the same scene master, environment/time, lighting, camera axis, furniture/prop state and recorded character screen positions. Compare the final narration panel with the clean dialogue scene side by side before animation. If the narration ends on a person-free B-roll insert, the cut into dialogue must be spatially motivated and restore the established dialogue composition without swapping sides or redesigning the set. Record a passed narration_dialogue_handoff in the dialogue render plan.

Transport approved originals through Google Drive under confirmed `darshan@en2.ai`: record file ID, fetchable image URL and hash; upload that URL through EN2; record returned upload name and visually compare it with the original. The payload uses returned upload names in visible-character, environment, visible-prop, composition-anchor order. New production always follows the approved scene/storyboard input; do not substitute an extracted video frame.

Follow [visual routing](../starling-animation-pack/references/visual-routing.md). Narration uses one approved full-frame scene when no meaningful cut is required, otherwise a black-and-white 1x2 or 1x3 storyboard with SHOT/time/CAMERA/ACTION labels below all pictures. Inspect all pictures and labels, then write a detailed description of each actual panel and its exact action/camera/timing using the current reference prompt template. Select attachments under [scene-matched reference selection](../starling-animation-pack/references/reference-bundle.md): only visible character identities and relevant props, in applicable group order; environment-only clips use environment and composition anchor. Shared multi-shot requests use the union of visible references while keeping per-shot visibility explicit. Rebuild reference indexes and remove omitted-subject prose after changes. Keep a clear gap between adjacent people. Use two or three edge-to-edge shots only when every hard cut has a distinct semantic purpose. Dialogue retains exactly one clean-scene ref, accepted speech and existing turn mapping. Record picture boxes, hashes, Drive/EN2 upload checks, measured audio mappings and shot_inventory_match. Narration plans use `narration_scene` with one shot and no cuts, or matching storyboard_1x2/storyboard_1x3 with shot_count minus one strictly increasing cut_times. Follow [buffered timing and visual review](../starling-animation-pack/references/timing-and-visual-review.md): each narration/establishing shot gets 1–2 seconds of buffer, with identical generated ranges and hard-cut times in printed storyboard labels and prompts. Save separate required edit timing and per-shot source_spans for trimming. The runtime validates structure, not visual truth. Reconcile older narration plans before new submissions; preserve paid IDs and media.

prepare-render CLIP PAYLOAD --kind narration returns a saved intent and exact tool arguments. The host submits once, then records actual provider ID using job INTENT queued --provider-id REAL_ID --evidence RESPONSE. Submit all ready clips in canonical order respecting provider limits. Review is not a hold between initial submission groups. Unknown outcomes use submission_unknown and are reconciled, not blindly retried. An initial visual failure permits one script-faithful scene redesign, inspected fresh images and one replacement animation; a second failure stops for user review. Retain the logical clip ID across redesigns. Runtime caps automatic replacements at one, including projects with an older higher setting; it does not judge scene fidelity. Animation prompts explicitly select 2D, 2.5D or 3D to match the inspected images.

Review every available output promptly during collection; preserve explicit pending/failed records for the rest. Check complete picture for visual hallucinations against each panel and repair observed defects through EN2 within the authorized attempt limit. Lip-sync is user-owned manual review, recorded separately; pending lip-sync is not a visual repair trigger. Full review is required for verified jobs; missing capability remains unverified. Read [POSTPRODUCTION.md](POSTPRODUCTION.md) for selected outputs, exact current manifests, stitching and final ZIP. FFmpeg still-image animation fallbacks are disabled.

After the complete initial render pass, the animation monitor can run as a ten-minute scheduled follow-up in the same chat when scheduling and connector access are demonstrated. It uses studio_queue for shared queue context and video_status for exact project IDs; `postproduction.py monitor-report` gives project counts and review scorecards. Record a real scheduled task ID only after a successful first run. Scheduling does not itself approve output or authorize paid replacements.
